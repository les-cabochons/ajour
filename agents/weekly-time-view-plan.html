A scoped plan for keeping the Time page timer-first while adding two quiet desktop weekly tools, one shared editor, explicit duplicate/move actions, settings-owned capacity, and resubmission after changes.

01 / Product outcome

Protect the timer loop; add a deliberate weekly workspace.

Opening Time must still lead directly to the selected day and its running timer. Week is a secondary desktop mode for allocation review, moving work between dates, comparing capacity, and preparing submission.

Final view hierarchy

Day is the default. Week is available at 1024px and wider with both Ledger and Lanes. Neither weekly style replaces or weakens the existing Day workflow.

In the feature

  • Dedicated Week entry and Day return actions
  • Ledger and Lanes weekly styles
  • One shared Day/Week entry form
  • Duplicate, Duplicate to…, and Move to…
  • Cross-day dragging for all stopped entries
  • Submitted-entry edits followed by resubmission
  • Settings-owned capacity and warning preferences
  • Desktop-only Week availability

Explicitly out

  • Calendar layout or start/end time persistence
  • Resize-to-change-duration behavior
  • Any mobile Week rendering
  • Dragging a running entry
  • Inline matrix duration editing
  • New remote submission semantics
02 / Interaction model

Enter Week deliberately; return to Day directly.

Day does not compete with Week in another segmented control. The Day toolbar gets one secondary “Week overview” action beside date navigation. Week replaces it with a clear “Day” return action and keeps the proven Ledger/Lanes toggle. The weekly style may persist locally; Week mode does not.

01Open Day

/time/$date renders the existing timer-first page.

02Open overview

Desktop users choose “Week overview” for the containing ISO week.

03Choose a lens

Ledger compares allocation; Lanes preserves entry context.

04Edit or organize

Double-click a Week entry to edit, duplicate, duplicate to another day, or move it.

05Return or submit

Open a day for timer work or submit through the existing review modal.

Ledger behavior

Rows group project/task work across seven days. Selecting a cell reveals its entries in a tray; double-clicking a tray entry opens the shared editor. Dragging still moves an eligible entry onto another weekday.

Lanes behavior

Each day is a column containing entry cards. A single click selects, a thresholded pointer movement drags, and double-click or Enter opens the shared editor in a modal. The destination receives a moved entry at the top of its saved ordering.

Drag and resubmit

Every stopped entry can move, including submitted entries. A move changes the submission fingerprint, clears the current submitted state through the existing transition rule, and returns that entry to the submit queue. Running entries remain locked. Keyboard “Move to…” performs the same mutation.

Desktop boundary

Week requires min-width: 1024px. At 1023px or narrower, hide Week controls and canonicalize any Week state back to Day. There is no mobile weekly substitute.

Capacity in Settings

Settings → General owns a duration target for each ISO weekday plus independent “Warn when over target” and “Warn when submitting under target” switches. Weekly capacity is the seven targets’ sum; zero-target days remain valid destinations.

One editor, two hosts

Extract the existing project/task, note, and hours controls into one entry form. Day keeps that form inline; Ledger and Lanes host it in a shadcn Dialog. When editing a saved stopped entry, its Entry actions menu contains Duplicate, Duplicate to…, and Move to… in every host; new-entry and running-timer forms do not show that menu.

Quiet capacity feedback

The toolbar and normal day headers show logged totals only. Hovering or focusing a total reveals its target and percentage. If enabled, exceeding a target adds a compact persistent warning; submitting below target opens a confirmation warning.

Submission logic stays unchanged.

The current fingerprint already includes localDate, and existing edits clear submittedAt when that fingerprint changes. A moved submitted entry therefore becomes unsubmitted and appears in the existing submit modal automatically. The optional under-target AlertDialog wraps the final submit trigger before it calls the same command; it does not change filters, selection, payloads, or remote semantics.

05 / Acceptance criteria

Observable behavior, including the boundaries.

Day remains primary

  • A normal Time route opens Day.
  • Timer creation, start, switch, stop, save, edit, reorder, restart, and delete remain unchanged.
  • Entry/timer search parameters still open the correct modal.
  • Week never becomes a persisted default mode.

Both Week styles

  • Ledger and Lanes use the same Monday–Sunday week and totals.
  • Switching styles preserves the week anchor.
  • The preferred style may persist locally.
  • Every Lane day header has the same width behavior and fixed height.

Dragging

  • Every stopped entry can move between dates in Ledger and Lanes.
  • Duration, project, task, note, work item, and source associations are preserved.
  • A moved submitted entry becomes unsubmitted through the existing fingerprint rule.
  • Running entries stay locked; keyboard “Move to…” matches pointer drag.

Shared editor and actions

  • Day’s inline editor and Week’s Dialog render the same TimeEntryForm fields and saved-entry actions.
  • Double-click and Enter open a stopped Week entry; drag still requires pointer movement beyond the threshold.
  • Duplicate creates an unsubmitted manual copy on the same day; Duplicate to… does so on the chosen date without reusing source-block provenance.
  • Move to… is available in Day and Week and produces the same transition as drag; new and running forms omit all three actions.

Capacity and warnings

  • Targets validate as finite, non-negative Settings values.
  • Normal headers show totals without persistent fractions or percentages.
  • Hover/focus exposes target and percentage; zero capacity yields “No target.”
  • Enabled over-target and under-target-on-submit warnings appear; each can be disabled.

Width boundary

  • Week is available at 1024px and wider.
  • At 1023px and narrower, Week controls are absent.
  • Narrowing an active Week view switches to Day.
  • No mobile Week markup or alternate weekly renderer ships.

shadcn ownership

  • Feature code imports controls only from components/ui.
  • Existing Dialog, DropdownMenu, Calendar, Button, ToggleGroup, HoverCard, Tooltip, AlertDialog, Switch, Table, Card, and Badge components are reused.
  • No new general-purpose UI primitive is required.
  • Custom code is limited to the shared form contract, entry commands, weekly rendering, derived capacity, and drag geometry.

08 / Locked product decisions

The scope is now explicit.

Implement Day plus two desktop Week styles.

The execution defaults are:

  • Day is the default; Week uses explicit enter/return actions and never appears below 1024px.
  • Day and Week share one entry form; Week opens it by double-click or Enter inside Dialog.
  • Duplicate, Duplicate to…, and Move to… live in that form everywhere, including Move to… from Day.
  • Ledger and equal-header Lanes both ship; all stopped entries can move and submitted changes are resubmitted through the existing workflow.
  • Targets and warning switches live in Settings; submission filtering, payloads, commands, and remote semantics remain unchanged.
