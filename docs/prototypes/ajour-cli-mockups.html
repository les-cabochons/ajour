ajour · a terminal for the running entry

One binary, ajour. Start, stop, fix and read time entries from any shell, with the same rules as the app. Scope for now: the running entry, saved entries and printing days and weeks. Workday is the commit target.

A day with it

Wednesday 4 November. Acme and Ajour projects, two pinned tasks. Every line below is also mocked in full further down.

09:02ajour start acme/backend -m "Rate limiter retries" · the entry runs on today, as in the app.
10:30ajour start 1 -m "Weekly sync" · pinned task 1. The running entry is saved and the new one starts at the same instant: a Switch, no prompt.
11:15ajour continue · back on the most recent entry, Rate limiter, which resumes with its 1:28.
12:00ajour stop · lunch.
13:20ajour start ajr/export -d 0:20 -m "Fix export rounding" · started 20 minutes late, so the entry counts on from 0:20.
15:00ajour add ajr/review -d 45m -m "PR #512" --on yesterday · a forgotten entry, saved straight onto Tuesday.
15:01ajour edit b7e1d04 -d 1:00 · it was an hour, really. Then ajour undo when it wasn't.
all dayajour status -s in the tmux status line: ● 1:24 Fix export rounding.
17:40ajour log · the day, with its total against the 8:00 target. ajour stop.
Fridayajour log week --format workday | wl-copy · the week as Workday lines: full project names, commit-as task names, hours with a comma, notes merged.

Command surface

Verbs sit at the top level because they are typed many times a day. Later areas get a namespace (ajour backlog …, ajour pr …). The vocabulary is the app's: nobody sees the word "timer".

$ ajour add ajr/review -d 45m -m "PR #512" --on yesterday

   1:00   AJR   04 Review     PR #512                       b7e1d04  Tue 3 Nov

$ ajour move b7e1d04 --to mon
   0:45   AJR   04 Review     PR #512                       b7e1d04  Mon 2 Nov

$ ajour dup 91c0aa3 --to fri              # duplicate to another day
   0:45   ACME  03 Meetings   Weekly sync                   f0a9d12  Fri 6 Nov

$ ajour rm f0a9d12 b7e1d04
Deleted 2 entries. Undo with: ajour undo

$ ajour edit 91c0aa3 -m "Weekly sync, moved to 10:30"    # a committed entry
   0:45   ACME  03 Meetings   Weekly sync, moved to 10:30   91c0aa3
Now differs from what Workday holds. It shows as updated on the Commit page.

Entry ids are 7 hex characters, as git shows them; any unique prefix works. running and last are named refs. Durations read 1:30, 1h30, 90m or 1.5, like the app's Hours field.

Usage: ajour [options] <command> [args]

Running entry

  completion SHELL        Shell completion for bash, zsh or fish.

  -V, --version

man ajour-log

AJOUR-LOG(1)                     Ajour Manual                     AJOUR-LOG(1)

NAME
       ajour-log - print time entries for a day, several days or a week

SYNOPSIS
       ajour log [RANGE] [--format FORMAT] [--by GROUP] [--summary]
                 [--project PROJECT] [--task TASK] [--committed|--uncommitted]

DESCRIPTION
       Prints the entries of a range of days, one line per entry, under a
       header with the range's total against its target. Without a RANGE
       it prints today. A running entry shows with ● and its time so far.

       Each line reads: state, duration, project code, task, note, a ✓
       when Workday holds the entry as it is, and the entry's id. Ids are
       what ajour edit, move, dup, rm and continue take.

RANGE
       today, yesterday
       mon .. sun         The most recent such day, today included.
       2026-11-03, 11-03  A date. Without a year, this year.
       DAY..DAY           Both days included, such as mon..wed or 10-28..11-03.
       week, last-week    Monday to Sunday.
       2026-W45           An ISO week.

OPTIONS
       --format FORMAT
              table (default on a terminal), workday, tsv (default in a
              pipe), csv, json.

              workday prints the Commit page's lines: the project's full
              name, the task's commit-as name, hours as a decimal with a
              comma, and the notes merged with " | ". Local only time,
              Not known yet tasks and the running entry are listed under
              the lines, not in them.

       --by GROUP
              day (default), task, or day-task. day-task is the default
              for --format workday.

       --summary, -s
              Totals per day only, with a bar against each day's target.

       --project PROJECT, --task TASK
              Only those entries. Same matching as a TASK argument, see
              ajour(1).

       --committed, --uncommitted
              Only entries Workday holds as they are, or only the rest.

EXAMPLES
       Today, on screen
              $ ajour log

       Last week for Workday, into the clipboard
              $ ajour log last-week --format workday | wl-copy

       Hours per task this week, as numbers
              $ ajour log week --by task --format tsv | cut -f2,4

       Notes of what is not committed yet
              $ ajour log week --uncommitted --json | jq -r '.entries[].note'

EXIT STATUS
       0 on success, 2 for a bad RANGE or option, 3 when Ajour is not
       reachable. See ajour(1) for the full list.

SEE ALSO
       ajour(1), ajour-start(1), ajour-add(1), ajour-undo(1)

man ajour · the shared sections

REFERENCES
       TASK   PROJECT/TASK or TASK. PROJECT matches a code, then a name;
              TASK a task name. Matching ignores case and accents and
              accepts a prefix, then any part of the name. Exactly one
              active task must match, else exit 4 with the candidates.
              A digit 1 to 0 is the pinned task with that key.

       ENTRY  An id from ajour log, or any unique prefix of it; running
              for the running entry; last for the entry saved most
              recently.

       DAY    today, yesterday, mon..sun, 2026-11-03 or 11-03.

       DURATION
              1:30, 1h30, 90m, 1.5 or 1,5. Whole minutes, up to 24 hours.

RULES
       A running entry is always on today. Starting while one runs saves
       it first and starts the new one at the same instant. The entries
       of a submitted week are read-only until the week is reopened in
       Ajour. Every change is the app's own action and shows its Undo
       toast there; ajour undo presses it.

OUTPUT
       Data goes to stdout, messages to stderr. On a terminal, prints
       use a table with color; in a pipe they use tab-separated values
       with no color. --json prints one object. Durations are h:mm on
       screen and decimal hours in machine formats.

ENVIRONMENT
       AJOUR_TOKEN      The client token, instead of the stored one.
       AJOUR_URL        The app's local address, default http://127.0.0.1:8787.
       NO_COLOR, CLICOLOR_FORCE
       AJOUR_CONFIG     The config file, default $XDG_CONFIG_HOME/ajour/config.toml.

FILES
       ~/.config/ajour/config.toml      url, color, default format, week start.
       The token lives in the OS keychain, never in the config file.

Rules that shape it

  • Same rules as the app. The CLI calls the MCP data tools, so a refusal is the app's reason, word for word, and every write has the Undo toast. No lifecycle logic lives in the CLI.
  • Vocabulary. Start, Switch, Stop, Continue, Discard, entry, saved, committed, submitted week. No "timer", no "log" as a noun; log is the verb, as in git.
  • Nothing leaves the machine. Loopback only, token in the keychain, no telemetry.
  • GNU manners. Short and long flags, -- ends options, - is stdin where it applies, --help on every command, man pages, exit codes, NO_COLOR, TTY detection.
  • One row shape. Writes answer with the row the prints use. Ids stay at the end, muted, so the eye reads duration, task, note.
  • Workday format mirrors the Commit page. Day and task grouping, full project names, commit-as task names, comma decimals, notes merged with " | ", local only and Not known yet called out below the lines.
